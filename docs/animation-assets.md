# Контракт ригов и производство ассетов

## Что готово в приложении

Загрузка `patient-rigged.glb` и необязательного `patient-anims.glb` через `useGLTF`, управление через `useAnimations`, независимые миксеры для поз и компрессий. Если отдельного файла клипов нет, используются встроенные анимации. Повреждённый файл, отсутствие кожи/скелета, несовместимые треки или обязательные клипы возвращают текущую составную модель. Риг кушетки загружается отдельно; до успешной проверки остаётся исходная кровать.

## Текущий ассет из A-pose.glb

Пользователь предоставил исходник `A-pose.glb`. Это одна статичная сетка Tripo: 49 658 треугольников, 28 459 вершин, исходные текстуры 4K. Оригинал сохранён; его точная копия лежит в `public/models/patient-a-pose-1.glb`.

Из него **локально, без GenAPI и новых платных запросов** подготовлен `public/models/patient-rigged.glb`: 27 костей с именами Mixamo, нормализованные веса кожи, 17 базовых клипов (в одном файле с мешем), два настоящих морфа `chest_rise` / `chest_compression`, текстуры 2K. Размер готового GLB — около 6,2 МиБ. Этот файл уже подхватывается загрузчиком в палате. Промежуточный риг в A-pose хранится в игнорируемом `exports/patient-source/patient-rig-base.glb`.

Это **черновой процедурный риг**, а не законченная ручная анимация: ещё нет рига пальцев и лицевых морфов `eyes_closed`, `pain_grimace`, `mouth_open_gasp`, `face_swelling`, `lips_swelling`. Не добавлялись фиктивные пустые targets. Точные контакты рук/таза, стоп с полом и позы на боку требуют ручной доработки. При нынешней высокой кровати сидящая пациентка не достаёт стопами до пола; IK не добавлен. Артикулированная GLB кровати пока отсутствует, поэтому сохраняется исходная кровать. Исходный резервный `patient.glb` не изменён.

Скрипты воспроизведения:

```bash
npm run prepare:patient-rig
npm run build:patient-animations
# Для 2K-экспорта нужен запущенный локальный Vite и Chrome на macOS:
npm run optimize:patient-textures
```

Первые два скрипта отказываются перезаписывать существующий результат; для отдельной версии используйте `-- --output /path/to/new.glb`, а у сборки клипов — при необходимости `--source /path/to/rig-base.glb`. Скрипт рига привязан к SHA-256 данного исходника и заданным анатомическим ориентирам; для другой модели их надо пересмотреть. Оптимизатор сохраняет отдельный `exports/patient-source/patient-rigged-2k.glb`; он не перезаписывает исходник. Ни одна из этих команд не обращается к платным API.

Технические проверки покрывают GLB, кости, веса, реальные ненулевые морфы и совпадение конечных кадров переходов с idle. Предпросмотры лежат в `exports/patient-source/`. Они не заменяют ручную художественную проверку. Треугольники из `tests/fixtures/` по-прежнему используются только в тестах загрузчика.

## Файлы и координаты

| Файл | Содержимое |
| --- | --- |
| `public/models/patient-a-pose-1.glb` … `-3.glb` | Неанимированные кандидаты из Tripo для отбора, не подключаются к сцене |
| `public/models/patient-rigged.glb` | Текущая пациентка: skinned mesh, 27 костей, 17 базовых клипов, дыхание/компрессия, текстуры 2K |
| `public/models/patient-anims.glb` | Необязательные клипы с той же арматурой и rest pose; совпадающие имена заменяют встроенные |
| `public/models/bed-articulated.glb` | Кушетка с костями и отдельной подушкой |
| `public/models/patient.glb` | Неприкосновенная резервная исходная модель |

Экспорт: glTF 2.0 binary, Y вверх, метры, объектные scale=1, текстуры встроены. До рига кандидат стоит в A-pose, pivot между ступнями. Финальные клипы создаются в общей Blender-сцене с кроватью: локальный origin используемого в R3F персонажа расположен у центра матраса, голова направлена к −Z, таз должен опираться на матрас. Геометрия/rest pose может оставаться в A-pose; её не должно быть видно после запуска лежачего клипа.

Подготовительный скрипт нормализовал данный риг до роста 1,8 м и направления +Z. Существующая сцена дополнительно не нормализует новый риг по bbox: это сломало бы единицы и анимационные треки. Калибровка пациента и одеяла продолжает применяться внешними группами. Origin кушетки в мире: `(-0.274, 1.3954, -2.0613)`, верх матраса у её локального `Y=0`. Автор должен проверить контакт с текущими настройками пациента `x=0, y=-0.28, z=-0.21, scale=1.5`. Произвольные изменения высоты и масштаба пользователя могут нарушить контакт стоп с полом; автоматический IK в этой реализации отсутствует. Настройки не сбрасываются.

Корневой объект не анимируется. Локальные смещения `Hips` для переката и контакта допустимы. Кости именуются по Mixamo; варианты `mixamorig:Hips`, `mixamorig_Hips`, `mixamorigHips` сопоставляются по имени. Это **не автоматический ретаргет** чужих пропорций/осей: отдельные клипы должны быть экспортированы с той же арматурой.

## Обязательные клипы

30 FPS. На границах переходных клипов позы совпадают с соседними idle. Переходы затухают/нарастают за 0,4 секунд симуляцииы. Острые состояния прерывают незавершённую цепочку: приложение не ждёт окончания подъёма на край кровати.

| Состояние | Idle |
| --- | --- |
| `lying` | `lying_idle` |
| `semifowler` | `semifowler_idle` |
| `sitting_edge` | `sit_edge_idle` |
| `legs_elevated` | `legs_elevated_idle` |
| `collapsed` | `collapsed_idle` |
| `arrest` | `arrest_idle` |

Обязательные одноразовые клипы: `lying_to_sit_edge` (около 4,5 с), `sit_edge_to_lying`, `faint_from_sit`. Они запускаются с `LoopOnce` и `clampWhenFinished`, затем включается idle. Дополнительные одноразовые переходы: `lying_to_semifowler`, `semifowler_to_lying`, `lying_to_legs_elevated`, `legs_elevated_to_lying`, `collapse_from_lying`, `collapsed_to_lying`, `arrest_to_lying`. Без дополнительного перехода работает crossfade между idle; это не заменяет художественно созданное движение.

`compression` обязателен, длится примерно 0,25–0,35 с и содержит **только** движение сжатия грудной клетки (лучше отдельный морф `chest_compression` или отдельную кость). Он перезапускается при увеличении числа компрессий. Его миксер идёт с масштабом 1, независимо от 1×/2×/4×; учебная пауза останавливает оба миксера. Не анимируйте в этом клипе голову, руки, корень и лицо. Если экспортер записывает весь массив morph weights, эти каналы временно принадлежат клипу; лучше экспортировать только нужный канал.

## Морфы и материалы

У предоставленной модели жёлто-зелёные пятна запечены в цветовую карту одежды.
`cleanRigClothing` корректирует только выделенный материал одежды `tripo_material_*`
при загрузке: заменяет цвет ткани на голубой, ослабляет запечённые тени и задаёт
матовую неметаллическую поверхность. Детали normal map и умеренная вариация яркости
сохраняются. Исходные GLB, кожа и анимации не изменяются; новая генерация не нужна.

Имена: `eyes_closed`, `pain_grimace`, `mouth_open_gasp`, `face_swelling`, `chest_rise`, `lips_swelling`. Отсутствующий морф даёт предупреждение и пропускается, не обрушая всю сцену. Глаза следуют сознанию; отёки — состоянию с затруднением дыхания и зудом; дыхание замирает при остановке и паузе. Эти эффекты — визуальное отображение имеющихся полей, не новая клиническая логика.

Кожные материалы называйте `skin_body`, `skin_face`, `lips` (или включайте `skin/face/lips` в имя). Runtime сохраняет исходные текстуры, меняет оттенок при бледности/покраснении и roughness при холодном поте. Маски сыпи, цианоз, кровь, дополнительные морфы и текстуры ещё требуют производства и отдельной привязки; они не изображаются как уже готовые эффекты.

## Кушетка и одеяло

Кости `Bed_Head`, `Bed_Knee`, `Bed_FootEnd`; локальная ось вращения X, bind rotation соответствует горизонтальному положению. Подголовник поднимается до 45° в `semifowler`; при `legs_elevated` работают коленная и ножная секции. `Bed_Pillow` — отдельный узел, скрывается при поднятых ногах и реанимации. Если риг успешно загружен, узлы старой кровати скрываются; ошибка возвращает старую кровать.

Существующее отдельное одеяло и его калибровка сохранены. При сидении, коллапсе и реанимации оно складывается и сдвигается к ногам. Cloth simulation и морфы самого одеяла пока не создаются.

## Производственный конвейер

1. Для текущей пациентки генерация уже выполнена пользователем: используйте предоставленный исходник. Новая генерация не нужна и не разрешена. Только для будущей явно согласованной генерации: `npm run generate:patient -- --dry-run` показывает запрос без ключа и без оплаты. Каждый обычный запуск — один платный запрос. `--variant 1`, `2`, `3` сохраняют кандидатов отдельно; повторная запись существующего варианта запрещена. ID сохраняется в `exports/generation-jobs/`; при обрыве используйте `--resume ID`, что не создаёт нового платного запроса. Неизвестный исход POST блокирует повторную отправку. Запрашиваются PBR, детальная геометрия/текстуры и лимит 50 тыс. полигонов; результат всё равно проверяется после оптимизации. Возраст оставлен 68 лет для согласования с данными сценария.
2. Отобрать модель с разделёнными конечностями. В Blender убрать запечённые тени, исправить локти/колени/плечи/таз, применить scale. Не пытаться авториггировать лежачую исходную сетку.
3. Mixamo/AccuRIG/Rigify или отдельный Meshy Rigging: исправить веса и проверить крайние позы. GenAPI Tripo H3.1 документирует статичную генерацию; Meshy Rigging принимает GLB через `model_url`, умеет авториг и необязательный пресет. Не предполагаем, что он создаст нужные медицинские клипы или морфы.
4. В одной сцене с кушеткой вручную создать клипы и shape keys. Контакт стоп, таза, локтей и качество кроссфейдов проверить в Blender и затем в приложении. Вручную проверить, что укладывание успевает к учебным интервалам 25/30 с при всех скоростях.
5. Экспортировать GLB, до 65 костей и 50 тыс. треугольников у пациентки, текстуры до 2K, суммарно до 30 МБ. Перед оптимизацией сохранить исходники. При glTF Transform не удалять/не объединять имена костей, клипов и морфов. Runtime поддерживает Meshopt, Draco и KTX2; локальные Draco/Basis декодеры входят в `public/decoders/`.
6. `npm run check:animation-assets` проверяет контейнеры, кожу/кости, клипы и размер. Это **не** проверка художественных деформаций, контакта или медицинской достоверности.
7. В `public/models/ATTRIBUTION.txt` и «Источники и методика» добавить реальные авторство, источник и лицензию каждого импортированного персонажа, реквизита и mocap. Сейчас новых сторонних персонажей/mocap нет.

Врач, 2–3 члена бригады, клипы ходьбы/передачи реанимации, артикулированная стойка и весь список медицинских props из запроса — следующий этап производства контента, а не результат загрузки `patient-rigged.glb`. Для них нужен отдельный набор моделей и анимаций.
